# HourLedger-Law

ניהול ודיווח שעות חיוב למשרדי עורכי דין. דיווח מהיר מהנייד, שורה נפרדת בגיליון לכל סוג חיוב, ודשבורד שמסכם שעות לפי לקוח או לפי חודש ורבעון.

אפליקציית דיווח שעות לנייד. קובץ HTML אחד, ללא תלויות, ללא שרת. מותאמת לכמה משרדים — כל משתמש מקבל את רשימת הלקוחות, הקטגוריות והסנכרון של המשרד שלו.

## מסכים

**כניסה** — קוד כניסה מהיר במכשיר מוכר, סיסמה מלאה כגיבוי, ופתיחת חשבון חדש בכניסה ראשונה.

**דיווח שעות** — תאריך (ברירת מחדל: היום), לקוח (רשימה נפתחת + הוספת לקוח חדש עם זיהוי כפילויות), קטגוריות חיוב (בחירה מרובה), שעות נפרדות לכל קטגוריה שנבחרה, הערות.

כל קטגוריה שנבחרת פותחת שורת שעות משלה, ונשלחת כשורה נפרדת לגיליון — אותו לקוח, אותו תאריך, חיוב אחר, שעות אחרות, ואותן הערות בכל השורות. שלוש קטגוריות בדיווח אחד = שלוש שורות בגיליון.

**דשבורד** — חיתוך לפי לקוח, לפי תאריך (חודשי / רבעוני) או לפי קטגוריה. סינון טווח תאריכים (החודש / חודש שעבר / הרבעון / השנה / טווח מותאם) שחל גם על ייצוא ה-CSV. בכל קבוצה פתוחה יש פירוט משנה: לקוח → לפי חודש, חודש או קטגוריה → לפי לקוח. החיתוך האחרון נשמר וחוזר בכניסה הבאה. כל שורת חיוב ניתנת לעריכה ולמחיקה בנפרד, והעדכון נשלח לגיליון לפי ה-`id` של אותה שורה. ייצוא CSV.

**הגדרות** — רשימת הלקוחות ורשימת קטגוריות החיוב (הוספה, הדבקה מרובה והסרה), סיסמה וקוד כניסה, פרטי החשבון, מצב הסנכרון והתנתקות.

## חשבונות וכניסה

מגרסה 4.0 החשבונות והנתונים נשמרים בענן (Supabase): נרשמים פעם אחת, ונכנסים מכל מכשיר עם מייל וסיסמה. יש "שכחתי סיסמה" ששולח קישור לאיפוס במייל. קוד הכניסה המהיר (4–6 ספרות) הוא קיצור דרך למכשיר הספציפי. ההגדרה מתוארת ב-`supabase/schema.sql` ובראש הסקריפט ב-`index.html`; בלי מפתחות, האפליקציה רצה במצב "מכשיר בלבד" כמתואר להלן.

אין משתמשים מוגדרים מראש, חוץ מחשבון דמו אחד (`demo@hourledger.app` / `Demo2026`) שמשמש להדגמה בלבד ונשאר מקומי למכשיר.

**כניסה ראשונה במכשיר** — מסך "פתיחת חשבון": אימייל, סיסמה (6 תווים ומעלה) וקוד כניסה מהיר בן 4 ספרות. שם המשרד קבוע לאתר (הקבוע `FIRM` ב-`index.html`) — אתר אחד לכל משרד. נפתח משרד חדש עם רשימת לקוחות ריקה, והמשתמש נוחת ישר במסך ההגדרות כדי להזין את הלקוחות שלו — אפשר להדביק רשימה שלמה, שם בכל שורה או מופרדים בפסיקים.

**כניסות הבאות באותו מכשיר** — מסך קוד הכניסה בלבד: שם המשרד, האימייל, וארבע ספרות. יש קישור ל"כניסה עם סיסמה" למי ששכח את הקוד, וקישור לפתיחת חשבון נוסף.

**שינוי סיסמה או קוד כניסה** — מסך ההגדרות, כרטיס "סיסמה וקוד כניסה": סיסמה נוכחית + מה שרוצים לשנות. אין צורך לגעת בקוד או בקונסולה.

הסיסמאות והקודים נשמרים כ-SHA-256 בלבד, במכשיר עצמו. המשמעות: חשבון קיים במכשיר שנפתח בו. מי שעובד גם מהמחשב וגם מהטלפון פותח חשבון בכל אחד מהם — הדיווחים נפגשים ממילא בגיליון. שחזור סיסמה, ומעבר חשבון בין מכשירים, דורשים שכבת שרת.

## העדפות שנשמרות לכל משתמש

רשימת הלקוחות, רשימת קטגוריות החיוב, והחיתוך האחרון שנבחר בדשבורד (לפי לקוח / לפי תאריך, חודשי / רבעוני) נשמרים לכל משתמש וחוזרים אוטומטית בכניסה הבאה.

## סנכרון לגוגל שיטס

כל שמירה, עריכה ומחיקה נשלחות ל-webhook של Make:

```
https://hook.eu1.make.com/3f461zbp81thyc76u95jzfs3yn6i5p1r
```

מבנה ה-JSON:

שורה אחת = בקשה אחת. דיווח עם שלוש קטגוריות שולח שלוש בקשות, כל אחת עם `id` משלה ו-`groupId` משותף.

```json
{
  "action": "create",
  "id": "m9x2k1a7b",
  "groupId": "m9x2k1a70",
  "date": "2026-09-12",
  "client": "ניצן באואר",
  "category": "דיון בבית משפט",
  "categoryId": "hearing",
  "hours": 1.75,
  "notes": "הכנה לדיון",
  "user": "office@law-weinberg.com",
  "org": "weinberg",
  "orgName": "משרד עו\"ד אורן וינברג",
  "source": "hourledger",
  "appVersion": "2.0",
  "timestamp": "2026-09-12T09:00:00.000Z"
}
```

`action` הוא `create`, `update` או `delete`. ה-`id` יציב לאורך חיי הרשומה — הוא המפתח לעדכון.

**התרחיש ב-Make:** Webhook → Router לפי `action`:

- `create` → Google Sheets · Add a Row (עמודה ראשונה = `id`)
- `update` → Google Sheets · Search Rows לפי `id` → Update a Row
- `delete` → Search Rows לפי `id` → Delete a Row (או סימון סטטוס "בוטל")

עמודות מומלצות בגיליון: `id`, `groupId`, `date`, `client`, `category`, `hours`, `notes`, `user`, `timestamp`.

`groupId` מאפשר לזהות אילו שורות הגיעו מאותו דיווח — שימושי לסיכום חיוב ליום ולקוח.

אם השליחה נכשלת (אין רשת), הרשומה נכנסת לתור מקומי, מופיע סימון "ממתין לסנכרון" בכותרת, והשליחה מתבצעת שוב אוטומטית כשחוזרת הרשת או בלחיצה על "שליחה חוזרת" במסך ההגדרות.

## העלאה ל-GitHub Pages

1. github.com → New repository → שם: `HourLedger-Law` → Public → Create.
2. בדף הריפו: Add file → Upload files → לגרור את `index.html`, `icon-192.png`, `logo.png`, `README.md` → Commit changes.
3. Settings → Pages → Source: Deploy from a branch → Branch: `main` / `/ (root)` → Save.
4. אחרי דקה הכתובת חיה: `https://waives-io.github.io/HourLedger-Law/`
5. בנייד: פתיחת הכתובת → Share → Add to Home Screen.

הריפו חייב להיות Public כדי ש-Pages יעבוד בחשבון חינמי. הקישור יהיה גלוי לכל מי שיש לו את הכתובת, ולכן הכניסה עם מייל וסיסמה היא מה שחוסם גישה — ואינה אבטחה ברמת שרת.

## בדיקות עם שני משתמשים

כל אחד פותח חשבון משלו במכשיר שלו ומזין את הלקוחות שלו. הגיליון ב-Google Sheets הוא המקום היחיד שבו הדיווחים של שניכם נפגשים — כל שורה נושאת שדה `user` שמזהה מי דיווח, אבל הדשבורד של כל אחד מציג רק את מה שהוא מילא.

## נתונים

הנתונים נשמרים מקומית במכשיר (localStorage), בנפרד לכל משרד, והגיליון ב-Google Sheets הוא העותק המרכזי.

## נגישות ומקלדת

Tab עובר בין השדות: תאריך → לקוח → קטגוריות → שורות השעות (אחת לכל קטגוריה) → הערות. בקטגוריות — חצים מדלגים בין הערכים, Space/Enter בוחר. ברשימת הלקוחות — חצים, Enter לבחירה, Esc לסגירה.
