# HourLedger-Law

ניהול ודיווח שעות חיוב למשרדי עורכי דין. דיווח מהיר מהנייד, שורה נפרדת בגיליון לכל סוג חיוב, ודשבורד שמסכם שעות לפי לקוח או לפי חודש ורבעון.

אפליקציית דיווח שעות לנייד. קובץ HTML אחד, ללא תלויות, ללא שרת. מותאמת לכמה משרדים — כל משתמש מקבל את רשימת הלקוחות, הקטגוריות והסנכרון של המשרד שלו.

## מסכים

**כניסה** — מייל וסיסמה, פעם אחת. המכשיר זוכר עד להתנתקות ידנית.

**דיווח שעות** — תאריך (ברירת מחדל: היום), לקוח (רשימה נפתחת + הוספת לקוח חדש עם זיהוי כפילויות), קטגוריות חיוב (בחירה מרובה), שעות נפרדות לכל קטגוריה שנבחרה, הערות.

כל קטגוריה שנבחרת פותחת שורת שעות משלה, ונשלחת כשורה נפרדת לגיליון — אותו לקוח, אותו תאריך, חיוב אחר, שעות אחרות, ואותן הערות בכל השורות. שלוש קטגוריות בדיווח אחד = שלוש שורות בגיליון.

**דשבורד** — חיתוך לפי לקוח (סיכום שעות לכל לקוח) או לפי תאריך (חודשי / רבעוני). כל שורת חיוב ניתנת לעריכה ולמחיקה בנפרד, והעדכון נשלח לגיליון לפי ה-`id` של אותה שורה. ייצוא CSV.

**הגדרות** — עריכת רשימת הלקוחות ורשימת קטגוריות החיוב (הוספה והסרה), פרטי החשבון, מצב הסנכרון והתנתקות.

## חשבונות

**משרד חדש** נרשם לבד ממסך הכניסה: "משרד חדש? פתיחת חשבון" → שם המשרד, אימייל, סיסמה וקוד הרשמה. הקוד הוא `WAIVES-2026` ונמצא בקבוע `SIGNUP_CODE` בקובץ — בלעדיו אי אפשר לפתוח חשבון, גם אם יש את הקישור. מומלץ להחליף אותו מדי פעם.

עם פתיחת החשבון נוצר "משרד" חדש עם רשימת לקוחות **ריקה** ורשימת קטגוריות ברירת מחדל, והמשתמש נוחת ישר במסך ההגדרות כדי להזין את הלקוחות שלו (אפשר להדביק רשימה שלמה בבת אחת — שם בכל שורה או מופרדים בפסיקים). כל הרשמה נשלחת גם ל-Make עם `action: "signup"`.

חשבונות שנפתחים בהרשמה נשמרים במכשיר שבו נרשמו. משתמש שרוצה לעבוד גם מהמחשב וגם מהטלפון נרשם בכל אחד מהם — הדיווחים נפגשים ממילא בגיליון.

## משתמשים מובנים

| מייל | סיסמה | משרד |
|---|---|---|
| `office@law-weinberg.com` | `Weinberg2026` | וינברג |
| `galli@waives.co.il` | `Moneh2026` | וינברג |
| `demo@hourledger.app` | `Demo2026` | משרד לדוגמה |

משתמשים מובנים מוגדרים בקוד ולא ניתן לדרוס אותם בהרשמה — ניסיון להירשם עם אימייל קיים נחסם.

**להחלפת סיסמה של משתמש מובנה או להוספת אחד:** לפתוח את האפליקציה, ובקונסולת הדפדפן להריץ

```js
await hourLedgerHash("someone@firm.co.il", "הסיסמה-החדשה")
```

ולהדביק את התוצאה כ-`hash` ברשימת `USERS` בקובץ. הסיסמאות עצמן לא נשמרות בקוד — רק SHA-256 שלהן.

> הכניסה חוסמת גישה למכשיר, אבל אינה אבטחת שרת: הקוד רץ בדפדפן והנתונים נשמרים מקומית. לניהול משתמשים אמיתי עם הרשאות צריך שכבת שרת.

## הוספת משרד לקוח חדש

בקובץ, באובייקט `ORGS`, להוסיף רשומה:

```js
newfirm: {
  he: 'משרד עו"ד ישראלי',
  en: "Israeli Law Office",
  webhook: "https://hook.eu1.make.com/...",
  clients: ["לקוח א", "לקוח ב"],
  categories: DEFAULT_CATEGORIES
}
```

ואז משתמש ב-`USERS` עם `org:"newfirm"`. מהרגע הזה הלקוחות והקטגוריות ניתנים לעריכה מתוך מסך ההגדרות.

## סנכרון לגוגל שיטס

כל שמירה, עריכה ומחיקה נשלחות ל-webhook של Make:

```
https://hook.eu1.make.com/3f461zbp81thyc76u95jzfs3yn6i5p1r
```

מבנה ה-JSON:

שורה אחת = בקשה אחת. דיווח עם שלוש קטגוריות שולח שלוש בקשות, כל אחת עם `id` משלה ו-`groupId` משותף.

```json
{
  "action": "create",
  "id": "m9x2k1a7b",
  "groupId": "m9x2k1a70",
  "date": "2026-09-12",
  "client": "ניצן באואר",
  "category": "דיון בבית משפט",
  "categoryId": "hearing",
  "hours": 1.75,
  "notes": "הכנה לדיון",
  "user": "office@law-weinberg.com",
  "org": "weinberg",
  "orgName": "משרד עו\"ד אורן וינברג",
  "source": "hourledger",
  "appVersion": "2.0",
  "timestamp": "2026-09-12T09:00:00.000Z"
}
```

`action` הוא `create`, `update` או `delete`. ה-`id` יציב לאורך חיי הרשומה — הוא המפתח לעדכון.

**התרחיש ב-Make:** Webhook → Router לפי `action`:

- `create` → Google Sheets · Add a Row (עמודה ראשונה = `id`)
- `update` → Google Sheets · Search Rows לפי `id` → Update a Row
- `delete` → Search Rows לפי `id` → Delete a Row (או סימון סטטוס "בוטל")

עמודות מומלצות בגיליון: `id`, `groupId`, `date`, `client`, `category`, `hours`, `notes`, `user`, `timestamp`.

`groupId` מאפשר לזהות אילו שורות הגיעו מאותו דיווח — שימושי לסיכום חיוב ליום ולקוח.

אם השליחה נכשלת (אין רשת), הרשומה נכנסת לתור מקומי, מופיע סימון "ממתין לסנכרון" בכותרת, והשליחה מתבצעת שוב אוטומטית כשחוזרת הרשת או בלחיצה על "שליחה חוזרת" במסך ההגדרות.

## העלאה ל-GitHub Pages

1. github.com → New repository → שם: `HourLedger-Law` → Public → Create.
2. בדף הריפו: Add file → Upload files → לגרור את `index.html`, `icon-192.png`, `logo.png`, `README.md` → Commit changes.
3. Settings → Pages → Source: Deploy from a branch → Branch: `main` / `/ (root)` → Save.
4. אחרי דקה הכתובת חיה: `https://waives-io.github.io/HourLedger-Law/`
5. בנייד: פתיחת הכתובת → Share → Add to Home Screen.

הריפו חייב להיות Public כדי ש-Pages יעבוד בחשבון חינמי. הקישור יהיה גלוי לכל מי שיש לו את הכתובת, ולכן הכניסה עם מייל וסיסמה היא מה שחוסם גישה — ואינה אבטחה ברמת שרת.

## בדיקות עם שני משתמשים

כל מכשיר וכל דפדפן מחזיקים עותק מקומי משלהם. הגיליון ב-Google Sheets הוא המקום היחיד שבו הדיווחים של שניכם נפגשים — אם את ואורן מדווחים במקביל, כל דיווח ייכנס לגיליון עם שדה `user` שמזהה מי דיווח, אבל הדשבורד של כל אחד יציג רק את מה שהוא מילא במכשיר שלו.

## נתונים

הנתונים נשמרים מקומית במכשיר (localStorage), בנפרד לכל משרד, והגיליון ב-Google Sheets הוא העותק המרכזי.

## נגישות ומקלדת

Tab עובר בין השדות: תאריך → לקוח → קטגוריות → שורות השעות (אחת לכל קטגוריה) → הערות. בקטגוריות — חצים מדלגים בין הערכים, Space/Enter בוחר. ברשימת הלקוחות — חצים, Enter לבחירה, Esc לסגירה.
